وقتی در مرورگر خود `google.com` را وارد می‌کنی، کامپیوتر قبل از اینکه بتواند به سرور متصل شود باید آدرس IP آن را پیدا کند.

اینجاست که **DNS** وارد می‌شود.

DNS مخفف **Domain Name System** است. وظیفه آن تبدیل نام‌های قابل‌فهم برای انسان، مثل `google.com`، به آدرس‌های IP مانند `142.250.185.14` است.

بدون DNS، برای باز کردن هر سایت باید آدرس IP آن را به خاطر می‌سپردیم.

## چرا به DNS نیاز داریم؟

کامپیوترها با آدرس‌های IP ارتباط برقرار می‌کنند، اما به خاطر سپردن نام برای انسان بسیار ساده‌تر است.

برای مثال:

```text
google.com
```

خیلی راحت‌تر از این است:

```text
142.250.185.14
```

DNS را می‌توان مانند یک دفترچه تلفن توزیع‌شده برای اینترنت در نظر گرفت.

فرآیند ساده‌شده به این شکل است:

```text
نام دامنه را وارد می‌کنی
       ↓
DNS Resolver
       ↓
DNS Server
       ↓
آدرس IP
       ↓
اتصال مرورگر به سرور
```

## DNS چگونه یک دامنه را پیدا می‌کند؟

وقتی یک دامنه را درخواست می‌کنی، کامپیوتر معمولاً مستقیماً سراغ Root DNS Server نمی‌رود.

چند مرحله مختلف در این فرآیند وجود دارد.

### ۱. کش محلی

ممکن است سیستم‌عامل از قبل آدرس IP دامنه را داشته باشد.

مرورگر، سیستم‌عامل و DNS Resolverها می‌توانند پاسخ‌های DNS را ذخیره کنند.

اگر پاسخ قبلاً در کش وجود داشته باشد، جستجو بسیار سریع‌تر انجام می‌شود.

### ۲. DNS Resolver

اگر پاسخ در کش موجود نباشد، دستگاه از یک DNS Resolver درخواست می‌کند.

معمولاً شرکت ارائه‌دهنده اینترنت یک DNS Resolver در اختیار دستگاه قرار می‌دهد، اما می‌توان از Resolverهای عمومی نیز استفاده کرد.

برای مثال:

| سرویس‌دهنده | DNS Server |
| ----------- | ---------- |
| Cloudflare  | `1.1.1.1`  |
| Google      | `8.8.8.8`  |
| Quad9       | `9.9.9.9`  |

Resolver وظیفه پیدا کردن پاسخ را برای دستگاه تو انجام می‌دهد.

### ۳. Root DNS Server

اگر Resolver پاسخ موردنظر را از قبل نداشته باشد، می‌تواند از یک Root DNS Server درخواست کند.

Root Server معمولاً آدرس IP نهایی را ارائه نمی‌دهد.

در عوض، Resolver را به سرور مربوط به **Top-Level Domain یا TLD** هدایت می‌کند.

برای مثال:

```text
example.com
       ↓
Root
       ↓
.com TLD
```

### ۴. Authoritative DNS Server

در نهایت Resolver به DNS Server معتبر یا **Authoritative DNS Server** مربوط به دامنه می‌رسد.

این سرور رکوردهای واقعی دامنه را در اختیار دارد.

برای مثال:

```text
example.com → 203.0.113.10
```

سپس پاسخ به Resolver و در نهایت به کامپیوتر تو برگردانده می‌شود.

## انواع رایج رکوردهای DNS

DNS رکوردهای مختلفی دارد که هرکدام کاربرد متفاوتی دارند.

### رکورد A

رکورد `A` یک نام دامنه را به یک آدرس IPv4 متصل می‌کند.

```text
example.com → 203.0.113.10
```

### رکورد AAAA

رکورد `AAAA` یک دامنه را به آدرس IPv6 متصل می‌کند.

```text
example.com → 2001:db8::10
```

### رکورد CNAME

رکورد `CNAME` یک نام مستعار برای دامنه دیگری ایجاد می‌کند.

```text
www.example.com → example.com
```

### رکورد MX

رکورد `MX` مشخص می‌کند ایمیل‌های یک دامنه باید به کدام Mail Server ارسال شوند.

```text
example.com → mail.example.com
```

### رکورد TXT

رکوردهای `TXT` می‌توانند اطلاعات متنی مختلفی را در خود نگه دارند.

از آن‌ها برای مواردی مانند تأیید مالکیت دامنه و سیستم‌های امنیتی ایمیل نیز استفاده می‌شود.

## بررسی DNS از طریق Command Line

برای بررسی DNS نیازی به ابزارهای پیچیده نداری.

در Windows می‌توانی از دستور زیر استفاده کنی:

```powershell
nslookup example.com
```

در Linux و macOS می‌توانی از `dig` استفاده کنی:

```bash
dig example.com
```

همچنین می‌توانی مشخص کنی که درخواست از طریق کدام DNS Resolver انجام شود.

برای مثال:

```bash
dig @1.1.1.1 example.com
```

این دستور از DNS Resolver شرکت Cloudflare برای پیدا کردن دامنه استفاده می‌کند.

## یک روش ساده برای عیب‌یابی DNS

وقتی یک سایت باز نمی‌شود، DNS یکی از اولین مواردی است که ارزش بررسی دارد.

ابتدا دامنه را بررسی کن:

```bash
nslookup example.com
```

اگر یک آدرس IP دریافت کردی، یعنی DNS حداقل در این مرحله توانسته دامنه را Resolve کند.

بعد می‌توانی اتصال را بررسی کنی:

```bash
ping example.com
```

همچنین می‌توانی نتیجه چند DNS Resolver مختلف را با یکدیگر مقایسه کنی:

```text
DNS شرکت ارائه‌دهنده اینترنت
          ↓
Cloudflare DNS
          ↓
Google DNS
```

اگر یک Resolver پاسخ بدهد اما Resolver دیگری نتواند دامنه را Resolve کند، مشکل ممکن است به تنظیمات DNS، کش، انتشار رکوردها یا خود Resolver مربوط باشد.

## DNS Cache چیست؟

پاسخ‌های DNS معمولاً برای مدتی در کش ذخیره می‌شوند.

مدت زمان ذخیره شدن پاسخ توسط مقداری به نام **TTL** مشخص می‌شود.

برای مثال:

```text
TTL: 3600
```

یعنی پاسخ می‌تواند معمولاً برای ۳۶۰۰ ثانیه در کش نگهداری شود.

کش کردن باعث کاهش درخواست‌های DNS و سریع‌تر شدن Lookupهای بعدی می‌شود.

البته همین موضوع می‌تواند باعث شود تغییرات DNS بلافاصله برای همه کاربران قابل مشاهده نباشد.

## DNS با اتصال اینترنت یکی نیست

یک اشتباه رایج این است که اگر سایتی باز نشد، تصور کنیم حتماً اتصال اینترنت مشکل دارد.

در واقع یک اتصال اینترنتی را می‌توان به چند مرحله تقسیم کرد:

```text
Internet Connection
       ↓
DNS Resolution
       ↓
TCP Connection
       ↓
TLS
       ↓
HTTP
       ↓
Application
```

مشکل در هرکدام از این لایه‌ها می‌تواند باعث باز نشدن سایت شود.

برای مثال:

* DNS ممکن است خراب باشد، در حالی که اینترنت کاملاً متصل است.
* DNS ممکن است درست کار کند، اما اتصال TCP برقرار نشود.
* TCP ممکن است برقرار شود، اما TLS با خطا مواجه شود.
* TLS ممکن است درست باشد، اما سرور HTTP خطا برگرداند.

به همین دلیل در عیب‌یابی شبکه بهتر است مشکل را مرحله‌به‌مرحله بررسی کنیم.

## دستورات کاربردی

چند دستور ساده برای بررسی DNS:

```bash
# Windows
nslookup example.com

# Linux / macOS
dig example.com

# Query Cloudflare DNS
dig @1.1.1.1 example.com

# Query Google's DNS
dig @8.8.8.8 example.com
```

در Windows می‌توانی کش DNS سیستم را نیز پاک کنی:

```powershell
ipconfig /flushdns
```

بعد از پاک کردن کش، دوباره دامنه را بررسی کن.

## چک‌لیست ساده عیب‌یابی DNS

وقتی با مشکل DNS مواجه شدی، این موارد را به ترتیب بررسی کن:

1. آیا دستگاه به اینترنت دسترسی دارد؟
2. آیا دامنه Resolve می‌شود؟
3. آیا DNS Resolver دیگری همان پاسخ را برمی‌گرداند؟
4. آیا رکوردهای DNS درست تنظیم شده‌اند؟
5. آیا پاسخ قدیمی در کش وجود دارد؟
6. آیا اتصال TCP برقرار می‌شود؟
7. آیا TLS به‌درستی کار می‌کند؟
8. آیا سرور HTTP پاسخ می‌دهد؟

> DNS فقط یکی از بخش‌های اتصال به یک سایت است. موفق بودن DNS Lookup به این معنی نیست که خود سایت نیز حتماً سالم است.

## جمع‌بندی

DNS یکی از سیستم‌های پایه و مهم اینترنت است.

وظیفه اصلی آن ساده است:

```text
Domain Name → IP Address
```

اما پشت این فرآیند ساده، یک سیستم توزیع‌شده شامل Cacheها، Resolverها، Root Serverها، TLD Serverها و Authoritative DNS Serverها قرار دارد.

شناخت DNS هنگام عیب‌یابی مشکلات شبکه بسیار کاربردی است، چون کمک می‌کند مشکل **تبدیل نام دامنه به IP** را از مشکلاتی که در مراحل بعدی اتصال اتفاق می‌افتند جدا کنیم.

وقتی این تفاوت را متوجه شوی، ابزارهایی مثل `nslookup` و `dig` خیلی بیشتر از یک تست ساده باز شدن سایت برایت کاربرد خواهند داشت.
